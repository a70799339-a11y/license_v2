# 04 · P2 规模化与权限说明

> 支撑 1000+ 家酒店的三项能力：分页虚拟滚动、告警聚合、权限分角色
> 更新：2026-11-04

## 一、分页 + 虚拟滚动（客户管理）

**后端** `GET /api/hotels/page`：
- 参数：page / page_size（≤500）/ keyword（名称/编号/集团模糊）/ status / plan
- 返回：{ items, total, page, pageSize }
- 数据库 LIKE 索引化后 1000+ 行毫秒级

**前端**（CustomersView）：
- **服务端分页**：默认 100 条/页（50/100/200 可选），筛选/搜索 300ms 防抖后回源
- **虚拟滚动**：el-table-v2 仅渲染可视区行，200 条/页滚动无卡顿
- 批量操作（续期/停用）基于当前页多选

**容量预估**：1000 家 × 30 设备 = 3 万设备行——设备清单页（客户详情 Tab）后续同样接分页即可。

## 二、告警聚合（AI 智能风控）

**后端** `GET /api/alerts/groups`：按规则聚合返回
```json
[{ "rule": "多设备并发激活", "level": "高", "count": 2, "pending": 1, "hotelCount": 2, "latest": "...", "sample": "..." }]
```
- 排序：待处理优先 → 次数倒序

**前端**：风控页默认「聚合视图」（哪类问题最多一眼看清），可切「明细视图」逐条处置。
千条告警时聚合视图行数 = 规则数（≤10），明细再按需翻页。

## 三、权限分角色（RBAC）

### 角色模型

| 角色 | 读 | 客户/授权/续期/告警处置 | 设置/用户管理 |
|---|---|---|---|
| admin | ✓ | ✓ | ✓ |
| operator | ✓ | ✓ | ✗（403） |
| viewer | ✓ | ✗（403 + 前端隐藏按钮） | ✗ |

### 实现

- **后端**：`require_roles("admin","operator")` 依赖注入守卫，登录 JWT 带 role 声明
- **前端**：Pinia auth store（role/isAdmin/canWrite）→ 按钮显隐 + 路由守卫（/users 仅 admin）
- **种子账号**：admin/admin123、ops/ops123、viewer/viewer123（旧库启动自动补齐）
- **用户管理**：GET/POST /api/users（admin），创建账号选角色

### 权限矩阵（测试覆盖）

| 操作 | admin | operator | viewer |
|---|---|---|---|
| 读客户列表 | 200 | 200 | 200 |
| 新增客户 | 200 | 200 | 403 |
| 修改设置 | 200 | 403 | 403 |
| 用户管理 | 200 | 403 | 403 |

## 五、总/子管理（集团）实现

- 数据：`groups` 表（集团码/套餐/到期）+ `hotels.group_id` 归属；启动幂等回填
- 客户端 token 带 `scope`（hotel/group）声明，心跳/自助/续期按 scope 分支
- 集团激活签发 group 级 Ed25519 License（载含成员数），心跳返回集团聚合状态
- 集团批量续期只作用于 `group_id` 匹配的门店（越权传其他门店 ID 不生效）并记审计日志
- 测试：T12 共 8 用例（激活/隔离/续期/越权/管理接口），62/62 全量通过
