## 二、测试环境（当前 WSL Ubuntu 24.04）

| 组件 | 位置 | 说明 |
|---|---|---|
| PostgreSQL 16 | systemd: postgresql | 库 license |
| FastAPI 后端 | systemd: license-backend | :8000，API + 前端静态托管 |
| Nginx | systemd: nginx | :80 → uvicorn:8000，入口 http://localhost |
| 前端产物 | /opt/license/backend/static | `npm run build` 后拷入 |
| 签名私钥 | /opt/license/backend/keys/ed25519.key | 权限 600，不入库 |
| 企微机器人凭据 | /opt/license/backend/wecom-bot.conf | 不入库（gitignore） |
| 本地大模型 | systemd: ollama（:11434） | qwen2.5 系列；llama.cpp 备选 :8080 |

### 日常命令

```bash
# 保活（防 WSL 休眠导致 404/502）
wsl -d Ubuntu-24.04 -u root -e sleep infinity

# 服务管理（含大模型）
wsl -d Ubuntu-24.04 -u root -e systemctl {status|restart} license-backend postgresql nginx ollama

# 看后端日志
wsl -d Ubuntu-24.04 -u root -e journalctl -u license-backend -n 50

# 全量回归（走 Nginx 入口；跑完自动还原模型配置快照）
BASE_URL=http://localhost python tests/run_tests.py

# 企微长连接状态
python tools/ws_status_check.py
```

注意：WSL 空闲休眠时 wslrelay 会回 404（客户端已内置自动重试）；长时间使用请挂保活。前端更新后需拷贝 `dist/` → `/opt/license/backend/static` 并重启 license-backend。

## 三、正式服务器部署（物理机/云主机）

前提：Linux x86_64（Ubuntu 22.04+ / CentOS 9+）、Python 3.11+、PostgreSQL 14+。

```bash
# 1. 取代码（git clone 含 backend/ deploy/ docs/；keys/ 与 wecom-bot.conf 不在库内，需单独带）
# 2. 装依赖
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt \
    -i https://mirrors.aliyun.com/pypi/simple/

# 3. 环境变量（systemd unit 或 .env）
DATABASE_URL=postgresql+psycopg2://user:pass@127.0.0.1:5432/license
JWT_SECRET=<强随机串>                 # 必改
LICENSE_KEY_PROVIDER=file             # 或 env/kms（见 02-安全加固指南）

# 4. 建库 + 启动（首次启动自动建表 + 种子）
createdb license
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000

# 5. 前端：npm ci && npm run build，产物放 backend/static/

# 6. systemd + Nginx 参考 deploy/license-backend.service 与 deploy/nginx.conf
```

### 生产必做清单

- [ ] 修改 admin/ops/viewer 默认口令；`JWT_SECRET` 换强随机串
- [ ] HTTPS（Nginx 证书）；防火墙只开 80/443
- [ ] 签名私钥 `backend/keys/` 权限 600、异地备份；勿入 git
- [ ] 企微机器人凭据 `backend/wecom-bot.conf` 同上（换服务器必须带上）
- [ ] PostgreSQL 每日自动备份（见 §六）
- [ ] 配置大模型接入（§五）与企微通知（§四）

## 四、企业微信机器人部署

1. **群机器人 webhook（推送）**：企微群 → 添加群机器人 → webhook 地址填后台「安全设计 → 企业微信通知」；集团群/门店群的 webhook 由客户在**自己客户端**配置（见 06/07），服务端自动按归属路由
2. **智能机器人长连接（指令/问答）**：
   - 企微后台「安全与管理 → 管理工具 → 智能机器人」创建，API 模式选**长连接**，拿 BotID + Secret
   - 写入服务端 `backend/wecom-bot.conf`（`WECHAT_BOT_ID=` / `WECHAT_BOT_SECRET=` / `WECHAT_BOT_ENABLED=on`），重启 license-backend
   - 状态验证：后台「安全设计」页看连接状态，或 `python tools/ws_status_check.py`
3. **用户绑定**：使用者 @机器人 发任意消息 → 把回复里的 userid 给我们 → `python tools/wecom_bind.py <userid> <姓名> <role>`（role：admin/operator/group——group 只能查本集团）
4. **指令**：状态/告警/续期（二次确认）；**自由文本由大模型回答**（经审计网关留痕）
5. dry-run 开关：调试期只记录不外发；上线时关闭

> 排障：认证报 `invalid bot_id or secret` = BotID/Secret 不配对（机器人重建后 BotID 会变）；认证无响应多为订阅频率保护，停服务冷却 20 分钟再启。

## 五、大模型接入（云端 + 本地双配置）

| 槽位 | 后端 | 部署 |
|---|---|---|
| 本地 | Ollama / llama.cpp | Ollama：`curl -fsSL https://ollama.com/install.sh \| sh`（需 zstd）→ `systemctl enable --now ollama` → `ollama pull qwen2.5:7b`；llama.cpp：`./server -m model.gguf --port 8080` |
| 云端 | OpenAI 兼容（DeepSeek/腾讯混元等） | 只需在后台填 endpoint(含/v1)/model/API Key |

配置入口：后台「安全设计 → 大模型调用审计」（本地行 + 云端行 + 激活槽位/失败兜底开关 + 测试连通）。
所有调用（告警 AI 解读、企微 AI 问答）统一经服务端审计网关，全量留痕并脱敏；**客户端永远不直连模型**。
调参：换模型改「模型名」保存即可；生产调用温度固定 0.3（稳定性与自然度平衡）。

### 本机实测选型（2026-11-06，i7-10750H + GTX 1650 Ti 4GB）

| 候选 | 清单完整* | 编造 | 速度 | 结论 |
|---|---|---|---|---|
| **qwen2.5:3b（发布主力）** | 依赖兜底 | 无 | 11~57 tok/s | 表述最好、诚实（数据不足会明说），速度快 |
| qwen2.5:1.5b | 不稳定（3/10 或 10/10） | 会顺着题面改口径 | 19~93 tok/s | 备选（冒烟/降级） |
| MiniCPM3-4B（GGUF 导入） | 9~10/10 | 无 | **2.9 tok/s** | 弃（一条 2 分钟，企微体验不可接受） |
| MiniCPM-2B | — | — | — | 未测（2023 老模型，指令遵循弱于以上） |

\* 小模型列清单普遍存在截断/不稳定——**清单正确性由系统「完整性兜底」保证**（模型输出条目少于数据条目数即自动切数据直出），模型只决定表述风格。

选型原则：数据查询准确性不依赖模型（接地+兜底双保险）；模型负责咨询类自然语言回答 → 综合速度/诚实度/表述选 qwen2.5:3b。本机 7B（Q4 混合推理 ~8-15 tok/s）可作质量升级选项，显存全速需 ≥8GB 卡。

## 六、备份、升级与发布

```bash
# 数据库每日备份（生产建议 cron 0 2 * * *）
pg_dump license > backup/license_$(date +%F).sql

# 发版流程
git pull && .venv/bin/pip install -r backend/requirements.txt
npm ci && npm run build && cp -r dist/* backend/static/
systemctl restart license-backend

# 客户端发版（本机构建）
client\build.bat release      # 单测/构建
client\bundle.bat             # NSIS 安装包 → client/src-tauri/target/release/bundle/nsis/
# 产物放 release/ 并更新后台 settings: client_version / client_download_url
# → 已安装客户端心跳自动提示「发现新版本」
```

数据保留策略：审计日志/LLM 调用日志不自动清理（可按年归档）；历史日志脱敏上线前的明文不回溯清洗（见 02）。

## 七、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 客户端 404/502 | WSL/服务未起 | 启保活 + `systemctl start license-backend postgresql nginx` |
| 激活报「设备已绑定其他酒店」 | 指纹冲突 | 后台解绑旧设备或换机激活 |
| 客户端「功能已禁用」 | 离线超宽限（默认 72h） | 连网自动恢复；时限在后台-安全设计可调 |
| 企微认证失败 | BotID/Secret 不配对 | 重建机器人后两值都要换；见 §四排障 |
| 企微 AI 答「模型未接入」 | 模型配置为空 | 后台配置本地/云端模型即生效 |
| 云端 Key 校验失败 | endpoint/key 错 | 后台「测试连通」看具体报错 |
| 磁盘涨得快 | Ollama 模型/备份 | 模型按需删（`ollama rm`）；备份轮转 |
