# 02 · 安全加固指南（商业化版）

> License 签发、防破解、密钥管理的加固现状与商业化升级路径
> 更新：2026-11-04

## 一、已实现的加固能力

### 1. 签名体系（防伪造）

- **Ed25519 非对称签名**：服务端私钥签发 License，客户端仅持公钥验签；任何字段篡改验签失败
- **规范化 JSON 载荷**：sort_keys + 紧凑分隔符 + 原始 UTF-8，Python/Rust 跨语言字节一致
- **跨语言验签已验证**：Python 签发（含中文字段）→ Rust 验签通过（tests + `cross_verify` 示例）

### 2. 私钥管理（KeyProvider 抽象）

私钥**不入库**（旧库存量启动时自动迁移删除），由 `backend/app/key_provider.py` 管理：

| Provider | 场景 | 配置 |
|---|---|---|
| `FileKeyProvider`（默认） | 自持服务器 | 私钥存 `backend/keys/ed25519.key`（权限 600） |
| `EnvKeyProvider` | 外部密钥系统注入 | `LICENSE_KEY_PROVIDER=env` + `LICENSE_SIGNING_KEY=<64字符hex>` |
| `KmsKeyProvider`（预留） | 云 KMS / HSM | `LICENSE_KEY_PROVIDER=kms`，按下方步骤接入 |

**接入云 KMS（腾讯云为例）**：
1. KMS 创建/托管 Ed25519 密钥，记录 key_id
2. `pip install tencentcloud-sdk-python-kms`
3. 在 `KmsKeyProvider` 中调用 KMS 签名 API（私钥永不出 KMS）
4. 配置云凭证（环境变量注入，禁止入库入码）

### 3. 客户端防破解（license-core）

| 能力 | 实现 |
|---|---|
| 设备指纹 | MachineGuid + 主机名 + 用户名 → SHA-256，一机一店绑定 |
| 凭证加密 | AES-256-GCM，密钥派生自设备指纹 + 混淆盐值（obfstr） |
| 防拷贝 | 心跳校验指纹一致性，凭证挪机 401 |
| 防时间回滚 | 记录历史服务端时间，倒退告警 |
| **反调试** | IsDebuggerPresent + CheckRemoteDebuggerPresent + NtQueryInformationProcess(ProcessDebugPort) + 时间侧信道；命中拒绝激活/验签并退出 |
| **字符串混淆** | obfstr 加密二进制中的敏感字符串 |
| **编译强化** | strip 符号剥离 + panic=abort + thin LTO + 关闭调试信息 |

### 4. 实时告警管道

检测点命中自动写入风控告警（去重 24h）：设备指纹变更、时间回滚、多设备并发激活、心跳中断、无效激活尝试、设备数超限、吊销后使用——运营在风控页看到真实事件并处置留痕。

### 5. 服务端安全

- JWT 24h 过期 + RBAC 三角色（admin/operator/viewer）
- 签发/吊销/处置全量审计日志
- 吊销必填原因；激活接口限设备数上限

## 二、商业化升级清单（按优先级）

| 优先级 | 项 | 说明 |
|---|---|---|
| P0 | 代码签名证书 | Windows 代码签名（EV 证书），消除 SmartScreen 拦截 |
| P0 | KMS/HSM 落地 | 按上文接入；私钥轮换策略（双密钥过渡签发） |
| P1 | 加壳保护 | VMProtect / Themida 对 license-core 模块加壳（GUI 壳不加，避免 WebView2 冲突） |
| P1 | 完整性自校验 | 启动时校验自身代码段哈希，被 patch 拒绝运行 |
| P1 | HTTPS + 证书锁定 | 心跳通道 TLS + 客户端内置服务端证书指纹 |
| P2 | License 轮换 | 定期重签短周期 License（如 7 天）+ 在线续签 |
| P2 | 渗透测试 | 上线前第三方渗透（重点：签发接口、客户端逆向） |

## 三、已知边界（诚实声明）

- 防破解是**提高破解成本**，不是绝对免疫；当前配置下破解成本已高于购买授权成本（个人破解者层面）
- FileKeyProvider 的 600 权限在 Windows 上为尽力而为，生产 Linux 部署必生效
- 时间侧信道检测在虚拟机里可能有误报（阈值 50ms），命中会拒绝激活——如遇误报可放宽 `anti_debug.rs` 阈值

## 四、密钥轮换操作（运维）

```bash
# 1. 备份旧密钥
cp backend/keys/ed25519.key backend/keys/ed25519.key.bak

# 2. 删除旧密钥文件并重启（自动生成新密钥对）
rm backend/keys/ed25519.key
systemctl restart license-backend

# 3. 客户端需重新激活（旧签名 License 在新公钥下验签失败，客户端会引导激活）
```
