## P0-1 · 客户端自助换机 / 解绑旧设备

### ✅ 已开发
- **数据模型**（models.py）：Device 增 `created_at`（激活速度检测）、`unbound_at`/`unbound_by`（软删痕迹：self/admin/migration）；status 扩展 `已解绑/已迁移`（软删保留，不物理删除）；幂等 DDL 已挂 main.py 启动迁移
- **客户端接口**（client_api.py）：
  - `GET /api/client/devices` — 设备清单（含软删行、is_self 标记、quota_left_today）
  - `POST /api/client/devices/unbind` — 校验：非本机 / 状态可解绑 / **离线 ≥30 分钟才可解绑**（阈值 `settings.unbind_offline_minutes` 可配）/ **每日 ≤3 次**（429）；释放配额；落 Alert「自助换机」（中）+ AuditLog；**7 天 ≥3 次升「频繁自助换机」（高）+ 企微推送**
  - `POST /api/client/devices/migrate` — 同名迁移（重装系统）：目标须同名+非本机+离线达标；旧设备置 `已迁移`
  - `POST /api/client/activate` 扩展 — 同名离线设备存在时返回 `migration_hint` + `migrate_target`；配额满但存在迁移候选时放行激活（替换语义）
- **管理端**（main.py + Vue）：`POST /api/hotels/{hid}/devices/{did}/restore`（E2 误操作恢复）；客户详情设备清单新增「解绑来源」列 + 已解绑/已迁移行「恢复」按钮
- **客户端**（main.rs + app.js + index.html）：设备页签新增操作列（解绑按钮+二次确认=E1）与今日剩余次数；激活后迁移提示确认框（confirm → migrate）；Rust 命令 `fetch_devices/unbind_device/migrate_device`
- **风控规则表**（SecurityView）：+「自助换机」「频繁自助换机」「激活速度异常」「僵尸复活」四条
- **回归测试**：T30.1 清单/配额、T30.2 在线拒解绑、T30.3 解绑成功、T30.4 本机拒解绑、T30.5 迁移提示、T30.6 迁移成功、T30.7 日限 429、T30.8 后台恢复

### T36 客户端凭证失效与重激活（2026-11-10 增补，源于真实事故）

| 用例 | 场景 | 断言 |
|---|---|---|
| T36.1 | 激活 → 心跳 | 200 + server_time |
| T36.2 | 失效凭证心跳 | 401「无效客户端凭证」（客户端据此走重激活，而非离线锁） |
| T36.3 | 静默重激活自愈 | 同指纹+授权码再激活 → 新 token → 心跳恢复 |
| T36.4 | 错误授权码重激活 | 404（引导人工，不死循环） |

**事故记录（2026-11-10 傍晚）**：客户机客户端显示「功能已禁用」，点「重新连接」无反应。
根因（crash.log 实锤）：心跳持续 `HTTP 401 无效客户端凭证`（服务端密钥轮换后旧 token 签名失效），
客户端把 401 当网络离线 → 套离线锁；「重新连接」只重试心跳永远撞 401；错误信息写在被遮罩盖住的 ov-msg 上 → 用户看到「毫无反应」。
修复（v1.2.1）：
1. **错误分类**（license-core `classify_api_error`）：401/403=鉴权失效≠离线，不再套离线锁误导
2. **静默重激活自愈**：鉴权失败自动用状态里存的 license_code 同指纹重激活（限 1 次防死循环），成功即恢复心跳
3. **可见反馈**：自愈失败时遮罩明确显示原因 +「去重新激活」按钮进激活页；同步失败提示写到遮罩上（不再隐身）

**T38 发现并修复的真实竞态缺陷**：
1. **激活超卖**：`hotel.devices >= max_devices` 检查与 `devices + 1` 更新非原子，双线程同时过检查双双建设备 → 修复：`with_for_update().populate_existing()` 行锁串行化同店激活（populate_existing 防身份映射返回旧值导致锁形同虚设）；独立复现脚本 `tests/client-accept/race_check.py` 5/5 验证。

## 事故与教训（防再犯，2026-11-11 归档）
