# 05 · 企业微信机器人接入方案（v0.2.0）

> 内部运营管理 + 集团客户管理双场景，与 License 系统事件管道对接
> 编制：2026-11-05 ｜ 状态：已实施（推送+指令管道），公网回调接入见 §6

## 一、目标

把 License 系统的**实时事件**（告警/到期/心跳中断/日报）通过企业微信送达对的人，并支持企微内**指令式管理**：

| 场景 | 使用者 | 价值 |
|---|---|---|
| **A. 内部管理** | 我们运营团队 | 高危告警秒级进群、每日运营日报、群里下指令查/续期 |
| **B. 集团管理** | 集团客户管理员 | 本集团门店告警/到期进自己企微群，不用装客户端也能管（总端客户端的轻量补充） |

## 二、总体架构

```
事件源（已有）                          企业微信
┌─────────────────────┐          ┌──────────────────────┐
│ raise_alert 实时告警  │──┐       │ 运营群机器人(webhook) │ ← 场景A
│ 心跳中断/到期扫描     │  ├─推送→│ 集团群机器人(webhook) │ ← 场景B
│ 每日运营/集团日报     │──┘       └──────────────────────┘
│                     │          ┌──────────────────────┐
│ 企微指令(查询/续期)   │←─回调──  │ 自建应用/智能机器人    │
└─────────────────────┘          └──────────────────────┘
        │权限与数据隔离：永远在服务端判定（group_id / RBAC）
        │敏感内容：推送前经 mask_text 脱敏（沿用日志脱敏管道）
```

## 三、功能设计

### 3.1 推送（两端共用管道，weCom.py）

| 事件 | 场景A 运营群 | 场景B 集团群 | 频控 |
|---|---|---|---|
| 紧急/高危告警（吊销后使用/指纹变更/并发激活/License共享） | ✅ 立即推 | ✅ 推本集团 | 即时 |
| 中危告警（无效激活/设备超限/心跳中断） | ✅ 进日报汇总 | ✅ 进集团日报 | 汇总 |
| 到期提醒（7 天内） | ✅ 日报 | ✅ 集团日报 | 每日 |
| 运营日报（新增告警/到期清单/异常门店） | ✅ 每日 09:00 | — | 每日 |
| 推送测试 | ✅ 手动按钮 | ✅ 手动按钮 | — |

- **日报触发**：读取告警/统计接口时惰性生成（当日首次访问触发，避免常驻定时器；生产可加 crontab 调 `/api/wecom/flush-daily`）
- **路由规则**：告警先按 `hotel → group_id` 找集团 webhook；运营群始终收全量
- **脱敏**：推送内容与日志同管道（mask_text），不传明文手机号/指纹/令牌

### 3.2 指令管道（weCom.py → process_command）

| 指令 | 示例 | 说明 | 权限 |
|---|---|---|---|
| 查状态 | `状态 HT-0001` | 返回授权状态/到期/设备数 | 需绑定 |
| 查告警 | `告警 HT-0001` | 最近告警 | 需绑定 |
| 续期 | `续期 HT-0001` | 续期一年（写审计） | operator+ 或集团绑定 |
| 帮助 | `帮助` | 指令列表 | — |

- **身份映射**：`wecom_bindings` 表（企微 userid → 集团/角色），未绑定用户仅能「帮助」
- **安全**：续期类操作需回复「确认续期 HT-xxxx」二次确认；全部指令进审计日志（脱敏）
- **通道**：自建应用回调 `POST /api/wecom/callback`（需公网 HTTPS）；本机调试用 `POST /api/wecom/simulate`（admin）直驱指令管道

### 3.3 配置（管理后台）

| 配置 | 位置 | 存储 |
|---|---|---|
| 运营群 webhook / 启用开关 / dry-run | 安全设计 → 企微通知 | settings |
| 各集团群 webhook | 集团管理 → 集团详情 | wecom_group_hooks 表 |
| 测试推送按钮 | 两处均有 | 即时发送验证 |

**dry-run 模式**：只记录不外发（`wecom_dry_run=on`），最近推送内容存 `wecom_last_push` 供测试断言——自动化测试全部走 dry-run。

## 四、安全边界

1. 权限判定在服务端：集团企微群**只见本集团**告警/数据（与客户端总端同一套 group_id 隔离）
2. webhook 地址视为密钥：接口返回掩码、写日志掩码
3. 指令二次确认 + 全量审计（脱敏管道覆盖）
4. 企微仅作通道：不在消息中传明文敏感字段

## 五、实施范围（v0.2.0 本次）

- ✅ 推送管道：告警路由（运营群+集团群）、日报生成、dry-run、测试推送
- ✅ 指令管道：process_command（状态/告警/续期/帮助）+ 二次确认 + simulate 调试接口
- ✅ wecom_bindings 身份映射表 + 绑定管理（API）
- ✅ 管理后台配置 UI（运营 webhook/集团 webhook/测试按钮）
- ✅ T16 测试 + 全量回归 + 文档 + 版本升级 0.2.0

## 六、后续（生产接入步骤）

1. 企业微信群里添加「群机器人」→ 复制 webhook 地址 → 填入后台配置 → 点「测试推送」
2. 集团客户在其企微群加机器人 → 把 webhook 给我们配置到对应集团
3. 双向指令：企微管理后台建**自建应用** → 配置回调 URL（需公网 HTTPS，如 `https://api.your-domain.com/api/wecom/callback`）→ 把 CorpID/Secret/Token/EncodingAESKey 配到后台 → 即可群内下指令
4. 可选：升级为企微「智能机器人」接入大模型做自然语言查询（见 docs/02 商业化清单）
