# 安全复盘与根因分析（2026-11-24）

> 触发：外部安全审计提出 9 条 issue（license_v2_security_issues.md），逐条核实 8 条属实、1 条部分属实、0 条虚报。
> 本文回答**为什么开发过程中会长出这些问题**，并给出防再发机制。修复进度见文末跟踪表。

---

## 一、9 条逐条归因

| # | 问题 | 直接根因 | 根因类型 |
|---|---|---|---|
| 1 | 客户端信任服务端下发的公钥 | 验签「回环」单测用本地生成密钥对，只验证了密码学原语正确——**没人问「公钥从哪来的」**。信任链被当实现细节 | 功能正确≠安全正确 |
| 2 | 客户编号可激活/可枚举/无限流 | 「编号好记」的产品体验决策落地时**没过威胁三问**；激活被当友好流程而非凭证流程 | 缺滥用场景设计 |
| 3 | group_renew 免付款续期 | P0-2 续期订单上马时**没回头盘「还有哪些途径能改 expire_at」**；写死 2027-12-31 是原型化石 | 加新不审旧 |
| 4 | 指纹校验可跳过（13 处） | 首处 `if fingerprint and ...` 是开发期宽容写法，**复制粘贴放大**；测试只测「错指纹拒」没测「缺指纹拒」 | fail-open + 复制粘贴 |
| 5 | viewer 读明文密钥 | get_settings 用**黑名单**（滤 `_` 前缀）而非白名单；后续 llm_cloud_api_key/webhook 新键入库**无审点**提醒「会进全量导出」。llm_config 自己有脱敏意识，同一标准没贯彻到通用接口 | 黑名单 + 新键无审点 |
| 6 | 默认弱口令自动创建 | seed 为演示便利，无环境门禁；登录无限流——同 #2「没想过有人会来试」 | 原型便利带进生产 |
| 7 | 部署无 TLS | 内网测试脚手架直接当生产用，**无生产就绪清单** | 生产硬化缺失 |
| 8 | CORS * + credentials | 教程默认代码 + 注释「生产收敛」——**TODO 写在注释里没进任务** | 安全债无跟踪位 |
| 9 | `==` 比较 + token 共钥 | 图省事实现；typ 校验只加在 client 侧没补 admin 侧 | 加新不审旧 |

## 二、五个系统性病根

1. **验收标准里从来没有攻击者**：全部回归验证「功能跑通」，零条验证「恶意输入/滥用被挡」。测试全绿 ≠ 安全。
2. **加新不审旧**：新功能只测新路径，从不回头盘同类敏感操作的旧入口（expire_at/#3、settings/#5、指纹/#4 均为此类）。
3. **宽容默认 fail-open**：缺头放行、HTTP、默认口令、CORS * ——开发期便利原样带进生产。
4. **安全债写在注释里**：「生产收敛」类 TODO 无任务位、无发版闸门，永远欠着。
5. **信任链当实现细节**：会用 Ed25519 ≠ 设计了信任模型。公钥分发、token 边界、凭证生命周期这类「谁信谁」的问题没有专门设计评审。

## 三、防再发机制（长期有效）

1. **威胁三问**（设计期）：每个对外接口（认证/激活/写操作）必答——谁能调？最坏能干嘛？要限流吗？答案写进模块开发记录。
2. **攻击者回归段**（测试期）：本次 9 条固化为回归断言（见 §四），漏洞修复必须伴随断言，防回潮。
3. **发版安全闸门**（发版期）：默认口令/传输加密/敏感数据导出面/宽容校验/旧路径复核，五问全过才打包（并入附录 A）。
4. **新功能回头审**（开发期）：新增「写敏感字段」能力时，列出所有能触达该字段的旧接口并纳入测试。
5. **敏感输出白名单制**（编码期）：禁止 denylist 过滤敏感数据；新敏感键入库时必须标注访问面。

## 六、第二轮复审（2026-11-25，N1~N13）

外部复审对第一轮修复做了回归验证：原 9 条中 5 条确认修复、3 条部分修复、1 条待外部（TLS），
并新发现 13 条（N1~N13），核实后**全部属实**。

### 6.1 第一轮修复为何还会漏（归因）

| 病根（复用 §二） | 本轮病例 |
|---|---|
| **加新不审旧**（再次命中） | S2 修了「酒店编号枚举」，没盘同类的**集团码 GP-0001** 也是顺序凭据（N1）；S2 加的限流键拼了客户端可控的指纹头（N2）——修了枚举却留了绕过 |
| **修复面不完整** | S3 堵了 group_renew API，没盘**同类免付款入口**：企微机器人「确认续期」仍直改到期日（N5）；S4 修了校验跳过，没盘**被校验的凭据本身在回显**（N4 指纹明文下发） |
| **fail-open 再现** | 设备复活不看原状态直接置「在线」且不回补配额（N3）；续期订单不校验套餐名、0 元可下单（N7） |
| **安全债又写在注释里** | N8 加密 nonce 固定，注释写着「商业化前换随机 nonce」——和 CORS 当年同款 |
| **黑名单思维** | N6 viewer 明文看授权码=激活凭据；flush-daily 对只读开放 |

新病根补充：**「修复只修报告点，不修攻击面」**——报告点名哪个入口就修哪个，
没有把「同一凭据/同一字段还有哪些暴露面」系统盘一遍（授权码→viewer 可见（N6），
指纹→所有设备列表明文（N4），集团码→激活凭据（N1）均为同型）。

### 6.2 修复与固化（2026-11-25）

- N1 集团激活码高熵化（GPK-token_hex(8)）+ 展示编号 GP- 403 + 存量回填
- N2 限流键改纯 IP（15min/10 次，settings activate_fail_limit 可调）+ uvicorn proxy-headers 取真实 IP
- N3 设备复活状态门禁（已禁用 403；已解绑/已迁移走配额回补+行锁）
- N4 指纹全链路打码（客户端 profile/devices + 管理端 DeviceOut）
- N5 企微续期双轨：内部角色直续按到期日顺延（去写死日期）；集团角色创建续期订单
- N6 viewer 授权码打码（mask_text 管道）；flush-daily 收 admin/operator
- N7 续期订单套餐存在性校验 + 0 元拒单
- N8 本地加密随机 nonce（LN2 魔数头+旧格式兼容）；N9 CSP 收紧
- N10 部署去硬编码口令（env.file 600 + 随机生成）；N11 银行卡掩码 raw 串修复；N12 限流字典封顶清理
